# Optional practice, deeper questions, and visual aids

## Offer without imposing

When a section is understood, make room for unanswered questions, a detail the
learner is curious about, or an everyday/practical application. Offer an
application suited to the explicit broader purpose and preferences, without forcing a weak
analogy. Deeper exploration/application is available whether or not the learner
wants a quiz. Preserve valid instructor analogies and the learner's agreed
interpretation separately in the notes. In Reviewer mode, include useful goal
connections directly; skip conversational offers unless a decision is needed.
Exam scope is the immediate objective, not evidence of broader purpose. Complete
the entrypoint's missing-purpose check before either mode starts. Exam-only and
skipped personalization use course-relevant examples without inferred interests.
Distinguish direct use from foundational connections. Record added examples and
instructor attribution in local progress; use only useful short teaching labels
in the PDF rather than workflow/provenance commentary.
Offer an optional knowledge check in the same short transition rather than stacking several menus.
Accept "move on", "I'm in a hurry", or "skip quizzes today" without pushing.
Remember a session-wide preference. An explanation is enough to move forward
when the user declines a test.

## Match the requested practice

Infer the form from the user's words; clarify only when scope matters. A quick
check may be a prediction or one analogous problem. A quiz uses short questions;
an activity asks the learner to produce or demonstrate something; a practice exam
can span discussed sections with a requested time/length/difficulty. Do not test
undiscussed material unless the user explicitly requests a diagnostic.

In conversational checks or a mock exam, let the learner answer before revealing
solutions. An explicitly requested side-by-side answer reviewer instead shows
answers immediately; follow [assessments.md](assessments.md) for both formats.
Give specific feedback on
reasoning, explain mistakes, and offer a retry or similar example if helpful.
Record observed understanding and remaining gaps, not an unsupported mastery
claim. Score only when requested or part of the agreed format. Keep answers
separate when creating a printable activity so the exercise is usable.

The default reviewer still has no embedded quiz. Ask whether accepted practice
belongs in the document, a separate activity, or only the conversation. A request
to test understanding does not authorize filling the reviewer with questions.
If practice exposes a misconception, discuss the correction and get agreement
before revising previously approved notes.

## Visual support when it helps

Keep the conversation in text, symbols, or equations when those explain the idea
clearly. Use a visual when it materially helps the learner see a relationship,
follow a difficult step, compare cases, or explore changing inputs. Do not add
decorative images, a control panel for every answer, or a separate app merely to
make the conversation look interactive. A visual supports the current discussion;
it does not replace the learner's response or establish understanding.

Prefer the relevant instructor diagram, screenshot, slide, rendered PDF excerpt,
or lecture frame. Inspect it before showing it directly in the conversation using
the host's supported image display. Crop to the useful region without removing
instructional labels or necessary context; exclude private overlays. Save the
original source file and page/slide/timestamp in local progress. If the source is
missing, unclear, or does not show the needed mechanism, create a focused diagram,
worked visual, animation, or simulation. Label it as a generated teaching aid,
preserve the original when useful, and distinguish additions from lecture claims.
Do not invent missing measurements, code behavior, or relationships.

No separate approval is required for a helpful conversational visual. Respect
explicit text-only preferences and saved visual choices. Ask only when a material
choice remains, such as a substantial detour beyond the current topic. Practice
still requires the learner's choice, and Review-mode additions to the reviewer
still require write-up approval; displaying an aid grants neither automatically.

Choose a medium that helps the concept: native Typst shapes/tables for print;
SVG/Mermaid for relationships; available image-generation tools for suitable
illustrations. When changing inputs or revealing steps helps, use supported inline
interactive content with only the useful buttons, tabs, sliders, or controls.
Use an available visualization skill and its display/verification contract rather
than assuming every chat renders HTML. Local control changes are not guaranteed
to reach the agent or save lesson progress; use supported follow-up actions or an
explicit learner reply for choices that must continue the conversation.
If inline interaction is unavailable, use a static image/diagram or a small local
demo in an available preview; state the limitation without claiming it rendered
in chat. No specific plugin or product is required. A PDF needs a legible static
representation. Display inline aids through the host's supported mechanism;
link a standalone demo when appropriate and include a checked snapshot/summary if
the user wants it in the reviewer. Do not host/upload it as part of local creation.

Check accuracy against sources and the discussed explanation. Render/view static
aids; for interactive demos, open the actual output and exercise relevant controls
using available browser tools, then capture and view a screenshot. Appearance
and behavior are separate checks. If tools are unavailable, record the limitation.
Save the aid's purpose, source/generated status, relevant paths, verification,
learner preferences and any document inclusion approval in progress before moving on.
